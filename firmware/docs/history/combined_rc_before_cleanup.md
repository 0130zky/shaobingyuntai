# C 板合体版：DM4310 拨盘 + 三个 M3508 摩擦轮

2026-10-30 架构改造：发射机构已拆为指令、三轮控制、拨盘控制和遥测编码，
由现有 PID 任务统一处理；修改位置与执行顺序见 [发射机构说明](modules/shooter/README.md)。
下方保留历史试验记录，当前保护阈值以 `dial_config.h` 和实际控制代码为准。

第二轮已隔离电机反馈与只读状态：显示和记录读取完整控制拍的快照，CAN 收包不再直接写控制对象。
遥测字段和通道顺序保留，主采样时间表示控制拍采样时刻；裁判帧年龄仍按打包时刻计算。

当前装配参数：4310 外部减速 3:1，8 槽，每步 45°。沿用已有 4310 闭环、量程和方向参数。

## 接线与电机配置

四个电机驱动器均接 C 板 **CAN1，1 Mbps**：

| 电机 | 驱动器 ID / 控制帧 | 反馈 ID |
| --- | --- | --- |
| 12 点摩擦轮 M3508/C620 | ID 1 / 0x200 槽 1 | 0x201 |
| 4 点摩擦轮 M3508/C620 | ID 2 / 0x200 槽 2 | 0x202 |
| 8 点摩擦轮 M3508/C620 | ID 3 / 0x200 槽 3 | 0x203 |
| DM4310 拨盘 | MIT 模式，ESC_ID=0x02 | MST_ID=0x12 |

旧 ID 4 的 3508 拨盘不再使用，0x200 槽 4 固定发零。4310 配置须与原台架一致：PMAX=12.5 rad、VMAX=30 rad/s、TMAX=10 N·m。
接收机通过 USART3 的 SBUS 输入；固件按 25 字节、0x0f 包头和 0x00 帧尾解码。

## 遥控操作

| 通道 | 行为 |
| --- | --- |
| CH6 | >1500（约 +100）总使能，其余位置停控 |
| CH8 | 三轮统一速度；-100~-80 停转，0 为 5560 rpm，+100 为 10000 rpm |
| CH5 = -100 | CH7 每次按下，进一格 45° |
| CH5 = 0 | 按住 CH7 分格连续进弹，到位停稳后间隔 150 ms 再走下一格 |
| CH5 = +100 | CH7 每次按下，退一格 45° |

上电前 CH6 关闭、CH8 旋钮逆时针到底、CH7 松开。使能后先低速检查三轮方向，再检查单步拨盘。
当前复测将 CH8 放在中位0，目标5560rpm。2026-10-28最近10条5750rpm弹速均值为17.008m/s，按5750×16.45/17.008估算约5561rpm，取5560先校正均值；这不是每发16.45±0.05m/s的保证。
重连或重新使能后须先松开 CH7，再按下才能触发。CH7 松开后不追加下一格，已开始的一格会走完。
CH6 关闭或超过 100 ms 无有效遥控帧时断力矩；SBUS 单帧丢失或错帧只丢弃该帧，不刷新在线时间；接收机失控标志会立即撤销链路有效状态。摩擦轮靠惯性滑停。
使能时拨盘仍沿用原逻辑对齐到最近 45° 档，最多移动 22.5°。

单独进弹/退弹与摩擦轮轮速无关。每次接受指令时锁定起点和终点，
起点取上一个锁定目标，终点固定增减45°；外部3:1时对应DM4310输出轴135°。
正常进退弹目标保持0°、45°、90°等固定网格，4°到位容差不参与下一格目标计算。
非零多发计数差值仅接受一格；动作未完成时丢弃新的正向进弹，不排队；反向动作也不能累加。
正向途中退弹会取消剩余进弹、返回本次原始起点；摩擦轮关闭时仍可单独进退弹。
连发仍等待拨盘到位和150ms停留。CH6总使能、遥控失联、拨盘反馈故障保护保留。
卡弹时只向原始起点回拨一次，最多22.5°且不越过本次45°区间；
到位停稳或回拨达到500ms后断输出并保持卡弹锁定，禁止自动前顶/连续重试。
需手动退弹解除锁定；重新使能只对齐当前位置，不恢复未完成动作。
每次正常进退弹的目标差固定45°，不按实测停止位置缩短下一格；中断退弹仍返回原格起点。
实测越界保护单独保留0.10°量化/停稳余量：实测距本次锁定起点超过45.10°、且偏离终点位置保持区时断输出锁定，需人工退弹或重新使能。目标跨度始终≤45°，余量不加入进退弹或回拨目标。
这是反馈采样后的越界停机，不是机械硬限位；采样延迟和惯性超调仍需空载验证，不能承诺物理零越界。
DM4310使能后持续运行位置/速度闭环保持，不再在±1°内清积分并卸力；PID增益保持不变。
三轮就绪仅作为遥测指标（误差±50rpm持续100ms），不拦截发弹。
速度环任务恢复原来的`PID_Task()`后相对`osDelay(3)`，摩擦轮PI增益不变。
DM4310拨盘恢复第一轮的位置环与包线抬速控制，配置值恢复450°/s；
它是旧包线的封顶值，并非新的硬限速。240/160°/s试验规划已撤回。
DM4310 带载供弹调整：速度环 Kp 从 0.0015 提到 0.00225，同样速度误差下比例推力增加 50%；
卡弹低速阈值从 33.85 降到 10°/s，持续时间从 120 延长到 300ms，允许低速顶推。
积分和最大力矩保留。单步45°目标边界及一次回拨后锁定对DM4310、3508共用。
这组值需要装机验证带载通过能力、到位超调和抖动，编译通过不代表实测通过。
保留USART6裁判115200接收、原始弹速/消息计数、USART1 25通道遥测和记录工具。

## USART1 转速调试

USART1（`huart1`）通过 DMA 输出 JustFloat 25 通道数据，每帧 104 字节，串口参数为 **460800、8N1、无流控**。
前十通道保持原顺序：12 点轮实测 rpm、4 点轮实测 rpm、8 点轮实测 rpm、统一目标 rpm、
裁判原始弹速 m/s、射击消息计数、最近射击消息接收 ms、当前采样 ms、
最近有效裁判帧距今 ms、发射机构 ID。
新增通道（以下编号从 1 起）：

| 通道 | 内容 | 单位/说明 |
| --- | --- | --- |
| 11～13 | 12/4/8 点轮电流指令 | 原始计数，±16384 为指令满量程；≥97% 可作为接近饱和的观测指标 |
| 14～16 | 12/4/8 点轮实际电流 | CAN 原始反馈计数，不直接标为安培 |
| 17～19 | 拨盘实际角度、目标角度、速度 | deg、deg、deg/s |
| 20～21 | 拨盘控制输出、实测力矩/电流 | 归一化值，±1 表示满量程 |
| 22～23 | 拨盘反馈正常、卡弹处理中 | 0/1 |
| 24 | 拨盘目标格编号 | Dial_Shoot，不等于测速弹丸总数 |
| 25 | 三轮稳速就绪 | 0/1，仅显示，不参与进弹门控 |

三轮速度、电流指令和反馈电流均按安装方向归一化，发射方向驱动为正，制动电流可为负。
拨盘与轮子在短临界区内读取，属于同一软件观测快照，但各电机 CAN 反馈并非物理同步采样。
射击计数和两个时间通道按 65536 回绕；无有效裁判帧或超时超过 65535ms 时，帧年龄为 65535。
弹速和射击时间保持最近一次值，计数变化才表示新射击消息，未收到射击消息时为 0。
接收时间是本板解析时刻，不是实际出膛时刻；裁判上报有延迟。
实测按安装方向（-、+、-）换算成发射方向为正，实际反转显示负值。
第 4 通道是最终命令，不是启动斜坡参考；USB 逐轮调试时仅代表 12 点轮目标。
数据由 Module_Task 每次循环尝试发送，串口忙时丢弃本次采样，不覆盖 DMA 缓冲区。

使用支持虚拟串口的 DAPLink：板端 USART1 TX（PA9）接 DAPLink RX，GND 接 GND，
电平使用 3.3 V TTL；仅查看曲线不必接板端 RX（PB7）。板端独立供电时不连接串口供电脚。
板卡丝印与 MCU 外设编号可能不同（旧代码注释称 USART1 为丝印 UART2），请按原理图确认接口。
在 VOFA+ 中选择 DAPLink 串口、**460800** 和 JustFloat 协议查看 25 通道曲线；数据不是文本。
可用无第三方依赖的工具保存 CSV（默认 460800、25 通道；旧固件可显式指定 `--baudrate 115200 --channels 10`）：

```sh
python3 tools/capture_friction.py --port /dev/cu.usbmodem3321071483003 --seconds 60 --output /tmp/friction.csv
```

脚本每秒刷新 CSV，Ctrl+C 可提前结束、保存并释放串口。
射击计数表示收到的测速消息数，不直接等于实际发射数；疑似重复上报须结合拨盘和掉速事件核对。

### 命令行后台持续记录

在本README所在目录执行（无第三方Python依赖）：

```sh
tools/shot_monitor.sh start --port /dev/cu.usbmodem3321071483003 --label baseline_5560
tools/shot_monitor.sh status
tools/shot_monitor.sh events --lines 20
tools/shot_monitor.sh stop
```

`start`会脱离当前终端持续运行，没有180秒限制；关终端后仍运行，重复启动不会开启第二个记录进程。
省略`--port`时，仅在找到唯一USB串口时自动选择。设备拔出后保留进程，按原端口路径自动重连；
端口名改变时应`stop`后用新`--port`重新启动。电脑关机或睡眠期间无法采集，脚本不设开机自启。
每次启动创建独立记录目录，默认`tools/records/monitor/日期时间_会话ID/`：

- `telemetry_0001.csv`等：25通道全部采样，每秒刷新，默认每30分钟分文件，停止时保存尾部数据。
  带主机Unix时间`host_unix_s`、会话相对秒`host_elapsed_s`及板载低16位毫秒时间；
  原有数值列名保持兼容`shot_scope`离线回放。两个低16位板载时间每65.536秒回绕。
- `events.jsonl`：带北京时间的连接/断线、射击消息、弹速是否在16.45±0.05内、卡弹、
  拨盘反馈异常、电流指令接近满量程、疑似反馈冻结/持续堵转等事件。疑似事件不是硬件诊断结论。
- `session.json`：启动参数、标签、本地编译产物指纹（不等于已核验板内版本）。
- 上级目录的`status.json`：最近采样、采样计数、连接状态、当前文件和异常标志；
  `daemon.log`记录进程错误。可随时让助手读取这些文件，无需重新开启一个限时测试。

串口一次只能由一个程序占用，后台记录时关闭VOFA+、GUI实时连接和限时采集脚本；
需要这些工具连接或固件烧录前先`stop`，完成后再`start`。离线回放不占串口。
记录器只读，不改变转速、不发弹、不清故障。重连首帧只建立消息计数基线，
断线期间的采样无法补回；消息计数变化也不保证每条都是一次独立实际发射。
长时间记录会持续占用磁盘，不会自动删除历史记录；请定期归档。
可用`run`代替`start`在前台运行，Ctrl+C停止并保存；`--directory`可指定记录根目录，
使用自定义目录后，`status/events/stop`也须带相同的`--directory`。

### 弹速上位机

`tools/shot_scope.py` 直接读这条 25 通道流，边采边算：

```sh
tools/shot_scope.sh                                   # 打开界面，选端口后点“连接”
tools/shot_scope.sh --replay tools/records/xxx.csv    # 离线回放已保存的记录
.venv/bin/python tools/shot_scope.py --self-test xxx.csv   # 不开界面，命令行出逐发统计
```

界面分四页：**轮速·电流**（三轮 rpm、目标、电流指令虚线 + 反馈实线，发弹处打竖线）、
**拨盘**（角度/目标、速度、电流）、**发弹对比**（把每一发按掉速起点对齐叠画，点左侧行可高亮）、
**原始通道**（25 路当前值）。左上角是逐发成绩单：弹速、Δ目标、每轮最低转速、恢复时间、
峰值电流、进弹前是否已到速，并按 `目标 ± 容差` 判 OK/偏高/偏低。

- 判定以“射击计数变化”为锚点，在 ±0.8s 窗口里找三轮平均转速最低点；
  `0.7s` 内弹速完全相同的那条自动标为**疑似重复上报**，不计入统计。
- 目标值与容差在左上角统计卡标题行；改完立刻按新值重判，无需重连。
- 点表格里某一发会把主视图挪到那一发附近并缩小窗口，叠图里同时高亮。
- 横轴用第 8 通道的板载毫秒重建，不受主机投递抖动影响。
- “开始记录”写 `tools/records/shot_<时间>.csv`（与 `capture_friction.py` 同列名），
  停止时另外导出一份 `_shots.csv` 逐发结果。`tools/records/` 已在 `tools/.gitignore` 里忽略。
- 连接、记录期间会独占这个串口，VOFA+ 和 `capture_friction.py` 必须先关掉。
- 连接会清空当前窗口数据并重新计时基；要留证据先点“开始记录”。
- 终端里 Ctrl+C 或关窗都会先停录、释放串口再退出。

裁判电源管理模块的学生串口 Tx/G 接 USART6 RX（PG9）/GND，USART6 固定为 115200、8N1。
该接收链路与 DAPLink 调试串口独立；裁判模块另一个串口不用于本测试。

## 构建与烧录

在本 README 所在目录执行：

```sh
cmake --preset DM4310
cmake --build --preset DM4310
bash tools/flash.sh -p DM4310 -n  # 只检查所选固件和命令
bash tools/flash.sh -b -p DM4310 # 编译、烧录、校验并复位运行
```

产物：`build/DM4310/robot_template.elf`、`.hex`、`.bin`。
请使用 DM4310 preset；已有 Debug/Release 缓存可能仍选择旧 RM3508。
DM4310Calib 是零力矩手转标定版，不能用于正常运行。
默认烧录脚本只寻找指定 preset 的产物，找不到时直接报错，不回退其他目录。

DM4310 preset 明确启用 `BOOSTER_RC_ONLY=ON`，USB 只回传遥测，不接收控制或零点指令；遥控掉线不会切换到 USB 控制。
需要恢复旧 USB 台架调试时，使用单独构建目录并显式设置 `-DDIAL_MOTOR=DM4310 -DBOOSTER_RC_ONLY=OFF`；DM4310Calib 已关闭该限制。

编译通过仅确认软件可生成固件。装机后的实际轮向、CAN ID、4310 量程、SBUS 通道和断联表现仍需在实物上核验。

上位机与后台记录同时使用：`tools/shot_scope.sh --monitor`。界面共享后台CSV，串口仍由`shot_monitor`独占；后台须先启动。

初始偏移：正常进弹为逆时针，固件默认顺时针1°（控制坐标−1°，保留2026-10-28板端确认的标定），后续固定网格为−1°、44°、89°……，每格仍为45°。
上位机`--monitor`界面新增“拨盘初始偏移”，顺时针为正，范围±10°、分辨率0.01°。
先关闭CH6，输入绝对偏移并点击应用；收到板端确认后重新使能。使能中请求会被拒绝，不排队。
该运行时设置掉电恢复固件默认1°。下行需DAPLink TX连接板载UART1 RX（PB7），后台保持串口唯一占用。
校准协议：A6 5A 01 + int16小端（控制角，0.01°）+前5字节异或；应答命令81表示应用、82表示使能中拒绝，应答数值为当前板端偏移。

三轮转速同步：保持共同目标（当前中位5560rpm）与原PI增益；按转速绝对值实现相同启动/减速斜坡，消除安装方向导致的75/150rpm斜坡差异。
控制前同时快照三路速度、目标、反馈时间；启动斜坡全部完成后，对相对三轮均速的差异追加0.30倍参考补偿，组内差≤30rpm时不补偿。
补偿统一缩放至每轮±100rpm以内、组内补偿和为零；三轮目标不同、任一反馈超过5ms、时间戳差超过1ms或异常转速时关闭同步项。
停轮、失联、反馈超时与发散锁存优先于同步；总参考和电流仍受原上限约束。此为初始保守参数，实际过弹同步效果需新一轮测试确认。

逐发三轮转速测量：`tools/shot_scope.sh --monitor --wheel-view`打开“单发三轮变化”。左侧选择一发；未选中时跟随最新发弹。显示三轮各自发前基线、独立最低转速、掉速rpm/百分比、发后转速及偏差、恢复时间、超调，并展示绝对转速和相对基线变化曲线。
时间0为三轮平均转速低于基线约2%/100rpm的遥测阈值，不是物理接触时刻。发前基线取掉速前300～50ms中位数；发后取起点后400～500ms均值；恢复从各轮最低点计时，需回到各自基线±100rpm并连续保持50ms。基线不稳、目标变化、采样断流分别标记；窗口内未恢复显示“—”，不作成功恢复处理。导出统计CSV新增逐轮测量列；原始采集继续由后台记录，现有记录可回放测量。

“单发三轮变化”三幅图分别叠加三轮实际rpm、相对各轮发前基线的Δrpm、电流反馈原始值；同色虚线为电流指令，可勾选显示。三幅图共用时间轴，可切换完整过程(-300～600ms)、过弹细节(-20～80ms)、恢复过程(0～200ms)。

## 三轮转速离线评估

在工程目录运行，复用后台记录，不占串口，不改变控制参数：

```sh
.venv/bin/python tools/evaluate_friction_wheels.py \
  tools/records/monitor/20261028_140208_43261a52 \
  --since 2026-10-28T14:31:21.598+08:00 --target 5782 \
  --out tools/records/evaluation/20261028_5782
```

输出`report.md`、`wheel_evaluation.png`、逐轮`shots.csv`和完整`evaluation.json`。按同一目标分组，评估发前瞬时误差、每发峰峰波动、同刻三轮差速、独立掉速、恢复时间与电流指令限幅情况；相邻350ms内且同一拨盘目标的成对裁判消息单列排除，避免混入独立加载比较。丢帧、调速、尚未到速等窗口给出排除原因，单纯轮速波动不会被筛掉。

恢复定义为从各轮最低点回到共同目标±100rpm并保持50ms，记录首次满足完整保持条件的起始时刻；窗口不足不判成功。遥测采样间隔不能代替PID执行周期，原始电流不换算为未经确认的安培数；120ms内最大轮间差包含恢复段，不能直接认作弹丸接触时差速。不同上电段保存在JSON的`by_block`中，禁止把不同目标/相位记录拼成单一弹速标定曲线。

## 控制时序与三轮同步诊断（2026-10-28）

本次保持PI增益、限幅、同步门槛和相对`osDelay(3)`调度不变。`PID_task.c`用独立CYCCNT差统计两次PID入口间隔及本次运行耗时（包含被抢占等待，不含末尾统计自身），不复用PI内部DWT时间戳。`booster_task.c`逐控制拍记录反馈年龄/时差、实际施加的同步补偿、含斜坡/补偿/钳位的PID参考、≥98%电流指令拍数和同步生效拍数；对外速度参考按发射正方向归一化。

USART1的25-float主帧及正无穷尾保持兼容。约每20ms用一帧24-float诊断替代一次主遥测发送，尾为`00 00 80 FF`；不阻塞控制任务，不增加逐拍主帧长度，但插入位置的主采样间隔会变长，应结合记录中的实际采样间隔评估。诊断帧前两项为版本1、最近完成控制拍的低16位毫秒时间。通道顺序见`tools/telemetry_io.py::DIAG_FIELDS`。每次取诊断帧时重置窗口峰值和拍数，其他观测保留；若DMA启动失败，该窗口可能丢失，拍序号与窗口拍数可用于识别覆盖缺口。

同步阻断码按现有检查顺序返回首个原因，另叠加爬升/保护位：`1`停轮或目标低于1000rpm、`2`三轮目标不一致、`4`反馈缺失或超过5ms、`8`三轮反馈时差超过1ms、`16`反馈速度超出0.5～1.25倍目标、`32`差速处于30rpm死区、`64`参考爬升中或保护锁存；`0`表示该拍同步通过门槛。死区内不补偿是正常状态。

新版后台解码两类帧并按接收顺序把最近诊断附到主采样CSV行，增加`diag_age_ms`；超过200ms或检测到板端时钟不连续时不再沿用诊断。诊断为20ms级观测，不能当成每3ms的真实补偿波形；限幅/补偿拍数与周期峰值覆盖整个回传窗口，不从低频瞬时值推算。旧固件/旧CSV无诊断时留空；VS Code仅绘制年龄不超过60ms的诊断。历史记录不能补出这些新指标。
